What is an API, and why do testers need it?

In plain words: an API is how screens and systems talk to the server: the app sends a request (“give me patient 1”) and gets back a response (a status code plus data). Many companies expect testers to check this layer, because bugs here affect every app that uses it, and you can test it before any screen exists.

☕ The waiter between the dining room and the kitchen. You test whether the right order reaches the kitchen and the right dish comes back, without needing to look at the menu board (the screen).

This is a safe, pretend server that lives in your browser (nothing is sent anywhere). It has 8 hidden bugs. Log in first to get a token: POST /login with {"user":"Sipho","password":"clinic123"} (Manager) or user Thabo (Doctor).

Status codes in one minute

200OK (it worked)
201Created (a new item was made)
204No content (worked, nothing to return)
400Bad request (your input is wrong)
401Not logged in / bad token
403Logged in but not allowed
404Not found
500Server broke (always a bug)
