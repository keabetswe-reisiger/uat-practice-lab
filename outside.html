Practice Outside the App

ReadinessHome

Why leave this app?

Everything here is built to teach you. Real software is messier, and real teams give you feedback you cannot get from a practice app. A hiring manager trusts evidence from real systems more than anything else. Do the tasks below, write what you find, and put the best results in your portfolio.
Rules for practising on other people's sites. Only test sites that invite testing (the ones below). Never run security scans, load tests or automated attacks against any site you do not own. Never enter real personal or payment details on a practice site. If you find a real security issue on a real company's site, do not exploit it: report it through the company's published security contact.

1. Free practice sites made for testers

Sauce Demo ↗

web shop

A small online shop with several test users (some deliberately broken). Task: log in as each user, add items, check out, and write 3 bug reports with steps, expected and actual.

Restful-Booker ↗

API

A booking API built for testers. Task: use a free API client (Postman, or the browser) to create, read, update and delete a booking, then try invalid data and missing authorisation.

ParaBank ↗

banking app

A demo bank with accounts, transfers and loans. Task: test a money transfer: boundary amounts, same-account transfer, and checking balances on both sides.

The Internet ↗

UI elements

A page of tricky web elements: dropdowns, drag and drop, alerts, file upload. Task: test five elements with the keyboard only (accessibility).

Automation Exercise ↗

e-commerce

A full demo shop with sign-up, cart and contact form. Task: write 10 test cases for the sign-up form (valid, invalid, boundary), run them, and record results.

DemoQA ↗

forms & widgets

Forms, tables and widgets to test. Task: test the practice form: required fields, email and phone formats, date picker boundaries.

Swagger Petstore ↗

API docs

A sample API with documentation you can try live. Task: read the documentation like a spec, then send a request that breaks one rule and record the response.

ReqRes ↗

API

A hosted test API for practising requests and responses. Task: check status codes for valid, missing and invalid input (200, 201, 400, 404).

2. Learn from real communities and courses

ISTQB Foundation Level ↗

The official syllabus, exam structure and free sample exams. Do these before you book. Real questions are worded differently from any practice material.

South African Software Testing Qualifications Board ↗

The local ISTQB member board: find where and how to write the exam in South Africa.

Ministry of Testing ↗

A friendly worldwide testing community: articles, talks and meet-ups. Read how working testers think.

Test Automation University ↗

Free courses on automation. Start when you are comfortable with the manual skills here.

Playwright ↗

A popular modern automation tool with good documentation. Try its “getting started” guide after the automation lessons.

Chrome DevTools guide ↗

The official guide for the tools in the DevTools lessons.

GitHub: Hello World ↗

A 10-minute official tutorial: make a repository, a branch, a commit and a pull request.

3. Get real experience (and real feedback)

uTest ↗

paid crowd testing

A community where testers are paid per accepted bug on real products. Read their academy and rules first. Early on, expect to learn more than you earn.

Open-source “good first issues” ↗

volunteer

Real projects label beginner-friendly tasks. Task: pick a small project, install it, try to reproduce an open bug report, and comment with your steps. Be polite and follow the project's guidelines.

Test something you already use

your own world

You run a coffee business. Test your own ordering, payment or stock tools: where does the screen disagree with the receipt? Write it up like a defect report. Real, honest, and unique to you.

4. A simple 4-week plan after you finish the app

  1. Week 1. Sauce Demo + ParaBank: write 6 bug reports with evidence (screenshots).
  2. Week 2. Restful-Booker: test 10 API requests, including 5 invalid ones; record status codes.
  3. Week 3. Take the official ISTQB sample exams under time. Review every wrong answer against the syllabus.
  4. Week 4. Build your portfolio, practise interviews out loud, then apply. Keep testing something every week.
